Setup guide
New City, New Site
Cloning the Studio Map pattern for a new city, worked example: Paris
Reference build: Berlin Studio Map (berlinstudiomap.com) · Updated 9 September 2026

Every step needed to take Berlin Studio Map's codebase and stand up a new city site, e.g. Paris. Each step is tagged LLM (Claude does it in the repo) or MANUAL (Dan does it by hand, usually a dashboard somewhere). One domain only, no plural variant, no local front-person required unless the site is a personal favour like Berlin's.

01Pick city, gather facts

Manual, before any code is touched.

Manual

Buy one domain, singular. e.g. parisstudiomap.com. Berlin owning both a singular and plural variant (berlinstudiomap.com + berlinstudiomaps.com) was a mistake from the first build, not a pattern to repeat: it meant a 301-redirect layer, a canonical-host check in the Worker, and four custom-domain routes instead of one. Buy via Cloudflare Registrar, keeps DNS + domain + Worker on one account.

Manual

Get city centre lat/lng and an area/district list. Hand the LLM: city centre coordinates (map default view + solar calc), a list of named districts to use as filter categories (5-12 is a good count, Berlin uses 10), and a rough lat/lng bounding box per district if the auto-detect-area-from-pin feature is wanted (optional, can hardcode area per studio instead).

Paris example: centre ~48.8566, 2.3522. Areas: Le Marais, Montmartre, Belleville, Bastille, Canal Saint-Martin, Pigalle, Batignolles, Les Gobelins.

02Fork / copy repo

Manual

Create a new GitHub repo. gh repo create paris-studio-map --public (or private). Don't fork Berlin's repo directly if the two need to diverge independently, a plain copy is cleaner.

Manual

Copy the codebase.

cp -R ~/Claude/berlin-studio-maps ~/Claude/paris-studio-map
cd ~/Claude/paris-studio-map
rm -rf .git node_modules dist .astro .wrangler beto
git init
npm install

beto/ is Berlin's gitignored build-log folder written for a specific friend, not needed in the clone.

LLM

Point the LLM at the new folder. Open a session in ~/Claude/paris-studio-map with a new project CLAUDE.md (copy Berlin's, strip the workspace table to this project). Every step below happens in that folder.

03Global find/replace pass

LLM task. Berlin Studio Map hardcodes the city name and domain in ~15 files, not one config constant. Grep, don't guess.

LLM

Grep for every hardcoded reference first.

grep -rniE "berlin|52\.5|13\.4" --include="*.astro" --include="*.ts" --include="*.mjs" --include="*.jsonc" --include="*.json" . | grep -v node_modules
FileWhat's in it
astro.config.mjssite: canonical URL
wrangler.jsoncworker name, single domain route, D1 database name
package.jsonname field
src/worker.tsFROM_ADDRESS, geocode query suffix (", Berlin, Germany"), User-Agent strings, email copy text. Delete the CANONICAL_HOST/OLD_HOSTS redirect block entirely, a single-domain site doesn't need it
src/layouts/PageLayout.astroJSON-LD Organization/WebSite, OG/Twitter meta, logo text, footer copyright, sun-position dark-mode calc (lat hardcoded)
src/pages/index.astrotitle/meta/OG/JSON-LD (duplicated from layout, this page has its own <head>), map center coords, city-lat const, area boundary boxes, logo text
src/pages/llms.txt.tsbase URL, every generated line of city-name copy
src/pages/about.astro, contact.astrotitle/canonical/JSON-LD, founder bio copy
src/pages/studios/index.astro, studios/[slug].astrometa/JSON-LD referencing city
src/pages/areas/[area].astro, features/[feature].astrometa/JSON-LD referencing city
src/pages/blog/*.astro (6 files)filenames themselves are city-suffixed, plus all body copy, titles, meta
LLM

Do the replace, file by file. Not a blind sed of "Berlin", too many false positives (blog filenames, area names like "Prenzlauer Berg" containing "Berg" not "Berlin", German-language copy). Swap:

  • "Berlin Studio Map" → "Paris Studio Map" (site name, everywhere)
  • domain strings → new domain
  • "in Berlin" / ", Berlin" copy fragments → "in Paris" / ", Paris"
  • "Berlin, Germany" geocode suffix in worker.ts → "Paris, France"
  • hello@berlinstudiomap.com → hello@parisstudiomap.com, must match the Email Routing address in phase 07
LLM

Rename blog post files and their slugs. *-berlin.astro → *-paris.astro, update internal links between them and blog/index.astro's listing.

04Geography: coords, area boundaries, solar calc

LLM

Update map center + solar calc latitude. In src/pages/index.astro: L.map('map', {center:[48.8566,2.3522], zoom:11}) and the city-lat constant (Berlin calls it BERLIN_LAT, rename it, cosmetic but avoids confusion). The same latitude value is duplicated inline in the dark-mode sun-position script in PageLayout.astro, keep both in sync.

LLM

Replace the AREAS bounding-box table. Same file, the object keyed by district name with [[lat,lng],[lat,lng]] boxes, used to auto-detect which area a pin falls in. Approximate from a map if exact boxes aren't available, it's a filter convenience, not precision GIS.

Manual

Sanity-check the solar calculator once live. Sunrise/sunset/golden-hour numbers on a studio page should look right for the new latitude and timezone. Paris shares Berlin's DST window so the hardcoded DST month range (Mar-Oct) needs no change; a non-European city would need that checked.

05Studio data

The single most time-consuming phase. Everything else is mechanical, this is real research.

LLM

Research real studios, one at a time, fact-checked. Populate src/data/studios.json:

{ id, name, area, neighbourhood, lat, lng, sqft, ceil, rate,
  daylight, blackout, cove, driveIn, kitchen, makeup, greenRoom, wifi,
  facing, extras: [], web, v: 0|1, email, badge }
Lesson from Berlin's data audit

Studios researched without a live web URL to verify against were disproportionately wrong on amenity flags (kitchen/makeup/cove/wifi/daylight) and rates. Don't add a studio unless its own website or a live listing (Google Maps, Instagram) confirms it's a real, currently-operating, rentable photo studio, not a photography agency, not an audio studio, not a permanently-closed venue. Mark "v": 1 only once checked against its own site.

Manual

Sync to public/.

cp src/data/studios.json public/studios.json

Two copies, must match, nothing auto-syncs them. Do this after every data edit, forgetting it is the single most common way this site drifts (the client-side map reads the public/ copy, everything else reads src/data/).

06Branding: name, favicon, OG image

Manual

Favicon/logo. Berlin's favicon was Beto Ruiz Alonso's own avatar, a marketing favour for a friend, not a required pattern. Paris doesn't need a credited local photographer or their imagery, a neutral generated icon is fine.

LLM

Regenerate the OG image. scripts/og/og-image.html is the source template (SVG-based, brand colours #0e0e0e bg / #e8a849 accent / #7eb8da cove-blue, reused as-is unless rebranding colours too), rendered via rsvg-convert -w 1200 -h 630 to public/og-image.png. Swap the city name text, rerun.

Manual

Get a Carto Basemaps API key. PUBLIC_CARTO_KEY in .env (copy .env.example). One key covers any number of sites, reuse Berlin's or get a new one at carto.com.

07Cloudflare: domain, D1, Turnstile, Email Routing, Analytics

All manual, done once in the Cloudflare dashboard (or API).

Manual

Add the domain to Cloudflare, note the account_id. Automatic if bought via Cloudflare Registrar. The account_id is needed for wrangler.jsonc.

Manual

Create the D1 database.

npx wrangler d1 create paris-studio-suggestions

Copy the returned database_id into wrangler.jsonc, then create both tables (contact_messages, suggestions) via wrangler d1 execute. Berlin's scripts/create-contact-messages-table.sql has the contact_messages schema. The suggestions table has no migration file in the repo, pull its schema from Berlin's live D1 first (wrangler d1 execute berlin-studio-suggestions --command ".schema suggestions"), and consider adding a migration file this time so the next city doesn't repeat the gap.

Manual

Create a Turnstile widget. Dashboard → Turnstile → add site, get sitekey + secret. Sitekey goes in wrangler.jsonc vars.TURNSTILE_SITEKEY (public, fine to commit). Secret is a Worker secret, never committed:

npx wrangler secret put TURNSTILE_SECRET
Manual

Set up Cloudflare Email Routing. Forward hello@parisstudiomap.com to Dan's real inbox. Dashboard → Email → Email Routing, add destination + routing rule. Free, no hosted mailbox needed.

Manual

Set up Cloudflare Web Analytics. One site for the one domain, auto_install: false, zone-level RUM auto-inject left off (avoids double-counting against the manual beacon in PageLayout.astro). Note the new site_tag + token, update the beacon snippet with them.

08Resend (email sending)

Manual

Verify the domain in Resend, get an API key. Resend dashboard → Domains → add parisstudiomap.com, add the DNS records it gives you in Cloudflare DNS, then generate an API key scoped to that domain.

npx wrangler secret put RESEND_API_KEY

09Deploy: Workers Builds git integration

Manual

Update wrangler.jsonc identifiers. Worker name, account_id, the single domain route, d1_databases block, vars.TURNSTILE_SITEKEY, all from the steps above.

Manual

Connect the Worker to the new GitHub repo. Dashboard → Workers → create → connect to Git, point at the new repo's main branch. Every push then auto-deploys, no GitHub Actions needed.

API gotcha, if scripting this instead of using the dashboard

POST /accounts/{account_id}/builds/workers rejects an otherwise-valid request unless previews_enabled and previews_base_config are included, despite neither being in Cloudflare's own documented schema. If wiring this via API, GET an existing working config first (e.g. Berlin's) and match its shape exactly rather than trusting the docs.

Manual

Add the custom domain route in Cloudflare, push to deploy. One route: { "pattern": "parisstudiomap.com", "custom_domain": true }. Once it matches a live Cloudflare custom-domain route and secrets are set, git push origin main triggers the first live deploy.

10Test checklist

  • Map loads, centered on new city, correct zoom
  • Dark/light auto-toggle matches actual local sunrise/sunset
  • Every studio pin sits in the correct district/area
  • Area filter dropdown lists new city's districts, correct counts
  • Studio detail page sunrise/sunset table looks right for the new latitude
  • Contact form sends and arrives (Turnstile passes, D1 row written)
  • Suggest-a-studio form: valid submission goes to pending, dupe/unreachable-site submission auto-rejects
  • /llms.txt renders with correct city name and studio/area/blog links
  • /sitemap-index.xml generates
  • robots.txt points at correct sitemap URL
  • OG image/meta correct when link is shared
  • Cloudflare Web Analytics dashboard shows traffic after a real visit
  • No leftover "Berlin" string anywhere: rerun the phase 03 grep as a final check
